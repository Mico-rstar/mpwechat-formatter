# 润色指导文档

本文档提供详细的润色规则和示例，指导如何改善文档的语言质量。

## 歧义检查规则（优先级最高）

在开始润色前，必须先检查用户输入是否存在歧义。歧义会导致润色结果不符合用户预期。

### 必须确认的场景

#### 1. 观点模糊

**问题示例**：
- "这个产品很好"（哪个产品？好在哪里？）
- "这个功能很有用"（哪个功能？对谁有用？）

**确认方式**：
```
您提到"这个产品很好"，请问：
1. 您指的是哪个产品？
2. 它好在哪些方面（性能、价格、用户体验）？
```

#### 2. 因果关系不明确

**问题示例**：
- "导致了这个问题"（什么导致了什么？）
- "因为技术进步"（技术进步导致了什么？）

**确认方式**：
```
您提到"导致了这个问题"，请问：
1. 是什么导致了这个问题？
2. 这个问题具体指什么？
```

#### 3. 术语歧义

**问题示例**：
- "AI改变了教育"（AI 指什么？机器学习、深度学习、大模型？）
- "使用云服务"（公有云、私有云、混合云？）

**确认方式**：
```
您提到"AI改变了教育"，请问：
1. 您指的 AI 是什么类型（机器学习、深度学习、大模型）？
2. 具体改变了教育的哪些方面？
```

#### 4. 缺少上下文

**问题示例**：
- "这很重要"（什么很重要？对谁重要？）
- "我们应该关注"（应该关注什么？）

**确认方式**：
```
您提到"这很重要"，请问：
1. "这"具体指什么？
2. 它对谁重要（用户、企业、行业）？
```

#### 5. 数据缺失

**问题示例**：
- "用户增长了很多"（从多少到多少？时间范围？）
- "成本降低了"（降低了多少？百分比还是绝对值？）

**确认方式**：
```
您提到"用户增长了很多"，请问：
1. 增长前是多少用户？增长后是多少？
2. 这个增长发生在多长时间内？
```

### 不需要确认的场景

以下情况可以直接润色，无需向用户确认：

1. **通用的过渡句**：如"然而"、"此外"、"因此"
2. **明确的陈述**：如"AI改变了教育行业"
3. **用户明确表示的个人信息**：如"我认为"、"在我看来"
4. **行业常识**：如"用户体验很重要"

## 文章层面歧义检查清单

在开始润色前，使用此清单检查文章的整体设定是否清晰。

### 1. 标题检查

**问题**：用户输入是否包含标题？

**检查方式**：
- 查看用户输入是否以 `#` 开头或明确标识为标题
- 如果没有标题，必须询问

**使用 `AskUserQuestion` 工具**：

```
Question: "注意到您没有提供文章标题。请选择标题方式："
Options:
- "生成选项" (description: "根据内容提供3个标题建议供选择")
- "自定义标题" (description: "您自己提供文章标题")
- "无需标题" (description: "文章不需要标题，直接开始正文")
```

**如果选择"生成选项"**：
- 分析文章核心内容
- 提供3个不同风格的标题建议
- 例如：
  1. 总结式："人工智能如何重塑教育行业"
  2. 提问式："AI时代，教育将走向何方？"
  3. 数据式："个性化学习：AI提升教育效率的3种方式"

**如果选择"自定义标题"**：
- 提示用户输入标题
- 确认标题是否满意

### 2. 语言风格确认

**问题**：文章应该采用什么样的语言风格？

**使用 `AskUserQuestion` 工具**：

```
Question: "请选择文章的语言风格："
Options:
- "正式专业" (description: "适合学术、行业分析、技术文档")
- "轻松通俗" (description: "适合科普、生活分享、大众阅读")
- "亲切口语" (description: "适合个人观点、随笔、情感表达")
- "自定义风格" (description: "描述您想要的语言风格特点")
```

**风格特征说明**：

| 风格 | 特征 | 词汇特点 | 句式特点 |
|------|------|----------|----------|
| 正式专业 | 客观、严谨 | 专业术语、书面语 | 长句为主、结构完整 |
| 轻松通俗 | 易懂、生动 | 常用词汇、比喻多 | 长短结合、节奏明快 |
| 亲切口语 | 接地气、真实 | 口语化、生活化 | 短句为主、自然流畅 |

**如果选择"自定义风格"**：
- 允许用户描述期望的语言特点
- 例如："像和朋友聊天一样"、"严肃但不要太学术"、"带点幽默感"

### 3. 目标读者确认

**问题**：文章是写给谁看的？

**重要性**：目标读者影响专业术语处理、举例方式、语言风格

**使用 `AskUserQuestion` 工具**：

```
Question: "请选择文章的目标读者："
Options:
- "普通大众" (description: "非专业人士，需要通俗易懂，避免术语")
- "行业从业者" (description: "有行业背景，可以使用专业术语")
- "技术人员" (description: "技术背景，可以深入技术细节")
- "决策者/管理者" (description: "关注商业价值、ROI、战略意义")
- "自定义读者" (description: "描述您的目标读者群体")
```

**基于目标读者的润色策略**：

| 目标读者 | 术语处理 | 举例方式 | 深度把握 |
|----------|----------|----------|----------|
| 普通大众 | 简化或解释术语 | 使用生活化例子 | 避免过度深入 |
| 行业从业者 | 正常使用术语 | 行业案例 | 适中深度 |
| 技术人员 | 可使用技术术语 | 技术案例 | 可深入细节 |
| 决策者 | 简化术语，强调价值 | 商业案例 | 聚焦价值点 |

### 4. 文章长度期望

**问题**：用户期望的文章长度是多少？

**使用 `AskUserQuestion` 工具**（仅当内容非常简短时询问）：

```
Question: "您当前的内容较为简短，期望扩展到什么长度？"
Options:
- "保持简洁" (description: "适度润色，不过度扩展，适合短文")
- "中等长度" (description: "适当扩展，增加到500-800字")
- "深度长文" (description: "大幅扩展，深入阐述，1000字以上")
- "根据内容自然" (description: "根据内容自然扩展，不刻意追求长度")
```

### 5. 配图需求确认

**问题**：文章是否需要配图？是否需要配图说明？

**检查方式**：
- 查看文章是否提到"图片"、"配图"、"截图"等
- 如果没有提及，询问是否需要添加配图说明

**使用 `AskUserQuestion` 工具**（当内容涉及产品、教程、数据时）：

```
Question: "您的文章是否需要配图说明？"
Options:
- "需要" (description: "会在相关位置标注[建议配图：xxx]")
- "不需要" (description: "纯文字文章，无需配图")
- "已有图片" (description: "图片已准备好，会插入相应位置")
```

**配图建议位置**：
- 开头：主题图/封面图
- 数据段落：数据图表
- 产品介绍：产品截图/实物图
- 教程步骤：步骤截图
- 结尾：总结图/行动号召图

### 5.5. 自定义风格需求确认

**问题**：用户是否需要自定义风格？

**重要性**：如果用户选择自定义风格，必须遵循微信公众号编辑器约束

**检查时机**：当用户在 Step 5 选择"自定义风格"时

**使用 `AskUserQuestion` 工具**：

```
Question: "请描述您想要的自定义风格特点："
Options:
- "温馨柔和" (description: "粉/暖色调，圆角边框，浅色背景")
- "商务专业" (description: "蓝/深色调，直线边框，严肃风格")
- "科技未来" (description: "深色背景，霓虹色，代码风格")
- "自定义描述" (description: "详细描述您想要的风格特点")
```

**生成自定义风格时必须遵守**：
1. **阅读** `references/custom-style-guide.md`
2. **容器宽度** ≤ 740px（关键约束，避免横向滚动）
3. **左右内边距** ≤ 20px
4. **正文字号** 16-17px
5. **行高** 1.75-1.85
6. **关键样式使用 !important**
7. **添加** word-wrap: break-word

**安全检查清单**：
```
✓ Container max-width ≤ 740px
✓ Padding ≤ 20px (left/right)
✓ Font-size 16-17px (body)
✓ Line-height 1.75-1.85
✓ !important on critical styles
✓ max-width: 100% on images
✓ word-wrap: break-word
```

### 6. 数据来源标注

**问题**：文章中是否有数据需要标注来源？

**检查方式**：
- 扫描文章中的数字、百分比、统计数据
- 如果有具体数据但未标注来源，询问用户

**确认方式**：
```
您的文章中包含以下数据：[列出数据]

请问：
1. 这些数据是否需要标注来源？
2. 来源信息是什么？（如："XX研究院2024年报告"）
```

**标注格式**：
- 标注在数据后的括号中
- 例如："用户增长200%（来源：XX公司2024Q1财报）"

### 7. 情感倾向确认

**问题**：文章的情感倾向是什么？

**重要性**：影响措辞、语气、立场表达

**使用 `AskUserQuestion` 工具**（当内容涉及争议话题时）：

```
Question: "请选择文章的情感倾向："
Options:
- "客观中立" (description: "中立陈述事实，不带个人立场")
- "明确支持" (description: "明确表达支持态度")
- "批判质疑" (description: "批判性观点，指出问题")
- "平衡观点" (description: "展示多方观点，不做偏向")
```

### 8. 专业术语处理

**问题**：如何处理专业术语？

**检查方式**：
- 识别文中的专业术语
- 结合目标读者确认处理方式

**使用 `AskUserQuestion` 工具**（当包含较多术语时）：

```
Question: "文章中包含一些专业术语，请选择处理方式："
Options:
- "保持原样" (description: "目标读者熟悉这些术语，无需解释")
- "首次解释" (description: "首次出现时简单解释")
- "简化表达" (description: "用通俗语言替代专业术语")
```

### 9. 结尾行动号召 (CTA)

**问题**：文章结尾是否需要添加行动号召？

**使用 `AskUserQuestion` 工具**：

```
Question: "文章结尾是否需要添加行动号召（CTA）？"
Options:
- "需要" (description: "添加关注、转发、点赞等引导")
```

**常见CTA类型**：
- 关注引导："欢迎关注我们，获取更多内容"
- 互动引导："如果您有不同观点，欢迎留言讨论"
- 转发引导："觉得有用？转发给更多人看到"
- 行动引导："立即体验XXX"

### 10. 时效性标注

**问题**：文章是否有时效性要求？

**检查方式**：
- 查看内容是否涉及特定时间点的信息
- 如果有时效性信息，询问是否需要标注

**确认方式**：
```
您的文章包含时效性信息：[具体信息]

请问是否需要添加时效性标注？例如：
- "截至2024年"
- "根据最新数据"
- "注：本文内容可能随时间变化"
```

## 润色原则

### 核心原则：只润色，不编造

润色的目标是改善语言质量，而不是添加新内容。

**允许的操作**：
- 改善词汇（很好→优秀，很多→大量）
- 调整句式（短句变长句，长句拆分）
- 添加过渡句（改善流畅度）
- 扩展现有观点（从不同角度解释）

**禁止的操作**：
- 添加用户未提及的信息
- 改变用户的观点
- 编造数据或例子
- 添加新的论点

### 段落扩展规则

**适用场景**：短段落（< 50字）可以适当扩展。

**扩展方法**：

1. **解释原因**：为什么这个观点重要？
2. **说明影响**：这个观点会带来什么结果？
3. **提供例子**：具体场景是什么？

**示例**：

**原始**：
```
AI改变教育。
```

**扩展后**（从原因、影响、例子三个角度）：
```
人工智能正在深刻改变教育行业。通过个性化学习算法，AI能够根据每个学生的学习进度和特点，提供定制化的学习内容和路径。这不仅提高了学习效率，也让教育更加公平和可及。
```

**注意**：扩展时只添加用户隐含表达的内容，不添加全新观点。

### 词汇改善示例

| 原词汇 | 改善后 | 原因 |
|-------|-------|------|
| 很好 | 优秀、出色 | 更具体 |
| 很多 | 大量、众多 | 更专业 |
| 重要 | 关键、核心 | 更有分量 |
| 快速 | 迅速、高效 | 更准确 |
| 大 | 巨大、显著 | 更有表现力 |

### 过渡句添加

在段落间添加过渡句，改善文章流畅度。

**常见过渡词**：
- 递进：此外、而且、 furthermore
- 转折：然而、但是、 nevertheless
- 因果：因此、所以、 consequently
- 总结：总的来说、综上所述

**示例**：

**原始**：
```
AI改变教育。个性化学习提升效率。
```

**添加过渡后**：
```
人工智能正在深刻改变教育行业。具体来说，通过个性化学习算法，学习效率得到了显著提升。
```

## 好的 vs 坏的润色对比

### 示例 1：改善词汇

**原始**：
```
这个产品很好，用户很喜欢。
```

**坏的润色**：
```
这个产品非常好，用户超级喜欢。
```
（只是加强了语气，没有实质改善）

**好的润色**：
```
该产品在用户体验方面表现优秀，受到了用户的广泛好评。
```
（改善了词汇，使表达更专业）

### 示例 2：段落扩展

**原始**：
```
AI改变教育。
```

**坏的润色**：
```
人工智能（AI）正在彻底改变整个教育行业，从幼儿园到大学，从线下到线上，从老师到学生，所有方面都在发生变化。
```
（添加了太多用户未提及的内容）

**好的润色**：
```
人工智能正在深刻改变教育行业。通过个性化学习算法，AI能够根据每个学生的学习进度和特点，提供定制化的学习内容和路径。
```
（扩展了"如何改变"这个隐含的内容，但没有添加全新观点）

### 示例 3：添加过渡

**原始**：
```
AI改变教育。个性化学习很重要。
```

**坏的润色**：
```
AI改变教育。此外，个性化学习也很重要。此外，效率也提升了。
```
（过度使用过渡词，显得机械）

**好的润色**：
```
人工智能正在深刻改变教育行业。其中，个性化学习是关键，它能根据学生的特点提供定制化内容，从而显著提升学习效率。
```
（自然地将两个观点连接起来）

### 示例 4：保持原意

**原始**：
```
这个产品好用，但不稳定。
```

**坏的润色**：
```
这个产品好用且稳定。
```
（改变了原意，原始指出了"不稳定"的问题）

**好的润色**：
```
该产品在易用性方面表现出色，但在稳定性方面仍有改进空间。
```
（保持了原意，但改善了表达）

## 润色技巧清单

在润色时，检查以下项目：

- [ ] 是否保持了用户的原意？
- [ ] 是否添加了用户未提及的信息？（应该避免）
- [ ] 词汇是否精准？（避免模糊词汇）
- [ ] 句式是否有变化？（避免单调）
- [ ] 段落间是否有过渡？（改善流畅度）
- [ ] 短段落是否适当扩展？（但不过度）
- [ ] 长段落是否考虑拆分？（> 150字）

## 常见问题

### Q1: 润色后文章变长了，正常吗？

A: 正常。润色会适度扩展内容，但通常不会超过原始长度的 2 倍。如果扩展过多，可能过度润色了。

### Q2: 用户要求"简洁润色"，怎么办？

A: 专注于改善词汇和句式，不要扩展内容。例如，将"很好"改为"优秀"，但不添加额外解释。

### Q3: 用户文档包含专业术语，需要解释吗？

A: 如果术语在目标读者中可能不清楚，可以添加简短解释。但不要过度解释，假设读者有基本背景知识。

### Q4: 如何判断润色是否过度？

A: 如果添加了用户未提及的新观点、数据或例子，就是过度润色。润色应该改善表达，而不是改变内容。

### Q5: 用户文档结构混乱，需要重新组织吗？

A: 首先使用 Format Guidelines 优化 Markdown 结构。如果仍然混乱，询问用户是否需要重新组织，不要擅自改变结构。
